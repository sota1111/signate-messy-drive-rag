## 3. 「5」と「7」それぞれの由来候補

### 3A. 回答「5」の由来（確定）

スライド18「変更管理方針」本文:
> 当初合意**スコープ外**の【追加分析、追加会議、成果物追加、再分析依頼、追加データ対応】等が発生した
> 場合は、影響範囲を確認のうえ、契約条件に従って別途対応する。

読点区切りで **5項目**（上表 g〜k）。「スコープ外」という語がこの文にのみ明示的に現れるため、モデルは
ここを「スコープ対象外の項目」と解釈して **5** を数えた。文書読解としては妥当な数え上げであり、**読み
違いではない**。

### 3B. gold「7」の最有力由来（推定・確証なし）

スライド18「前提条件」の ✓ **7項目**:
1. 目的変数diseaseは肝疾患の有無（0:無, 1:有）である
2. idはインデックス用途であり、予測特徴量として使用しない
3. 入力データはdata\train.csvの単一ファイルを対象とする
4. 欠損値は存在しない前提だが、値妥当性の検証は実施する
5. 分析結果は診断の代替ではなく、判定支援材料として利用する
6. 評価は学習データ内の適切な分割・検証に基づいて実施する
7. 時系列情報がないため、経時変化分析は実施しない

ちょうど 7 項目で、うち複数（2・3・5・7）が実質「〜は対象外／〜はしない」という**スコープ境界の宣言**。
採点者が「前提条件（＝スコープの外枠を定義する制約）」を「スコープ対象外」と読んだ場合に **7** が出る。
ただしラベルは「前提条件」であり「スコープ対象外」ではないため、**文書の字面から一意に導けない**。

他の 7 候補（例: §2 の a〜k から任意に 7 を選ぶ）は恣意的で再現性が無い。

- idx27 は **archetype=真値誤り**ではなく **問い⇄文書ラベルの解釈相違**。決定論ストアで安全に回収する
  には文書内に一意の「スコープ対象外」列挙が必要だが、それが**存在しない**。

  採点解釈が妥当かを人間が確認する軸になる。本 K6 のスコープ（idx79 単位strip）とは別軸のため分離する。
