# SOT-2457 — 回答精度が上がらない原因調査（root-cause analysis）

_Date: 2026-08-05 · Scope: 実提出6件（−0.2333 → −0.0667 → −0.0333 → −0.1000 → −0.1333 → −0.1333）_

## TL;DR — 精度が上がらない4つの構造要因

1. **最適化の羅針盤が壊れている。** ローカル評価（valid30 / synth hold-out / real-style bench）と実Public
   スコアの相関は **Spearman −0.0896（6提出）** — 無相関どころか僅かに逆相関。ローカルの改善証拠で採用
   した変更は実LBで2回退行し（#4, #5）、1回は無効果だった（#6）。改善サイクル自体はずっと回っているが、
   **ノイズ（または逆信号）に向かって最適化している**ため実スコアが上がらない。
2. **実スコアを上げた唯一のレバー（棄権強化）は上限 0.0 の道。** #1→#3 の改善（−0.2333→−0.0333）は
   ほぼ全てコミット数削減（30→24問、net誤答 −7→−1）による。全問棄権＝0.0 が漸近上限で、正の得点には
   **コミット回答の実精度 >50%**（Incorrect=−1 の損益分岐）が必要。それは一度も実証されていない。
3. **未知設問でコミット精度が崩壊する。** valid30（開発で参照済み）ではコミット精度 92.5%（18P+1A+1I/20
   コミット）だが、実test公開30問では概算 **25〜40%**（net −4、コミット率27%からの推定）。コミット率も
   valid 67%（20/30）→ test 27%（27/100）に崩落しており、**未知の設問に対して検索・抽出が証拠を出せて
   いない**（coverage欠損）ことを示す。上位11チームは 1.0（30/30全問正解）— 答えはコーパス内に必ず存在
   するので、これは能力上限ではなく取りこぼし。
4. **最良提出（#3, −0.0333）の回答セットを喪失し、基盤が −0.1333 に凍結。** #3 の回答ファイルは
   gitignore（`*.zip` / `/artifacts/`）でコミットされず復元不能（LLM非決定性のため再実行でも同一回答は
   得られない）。SOT-2424..2428 で再構築した基盤は −0.1333 と実測で悪化。以降の候補（#6正規化、R1
   fact索引、R3 RRF4、R4 rerank）は全て二軸ゲートで棄却または挙動同一で、**3提出連続でほぼ同一の
   既知劣位挙動（−0.1333）を再提出**した。

## ローカル評価が実LBと無相関な理由（3つの独立メカニズム）

1. **valid30過適合（#4の敗因）**: 加点モジュールを既知30問に対して開発 → 未知設問では確信を持った
   誤答を量産（各−1）。valid30 +0.5833 → 実 −0.10。
2. **synth/hold-outの循環性（#5の敗因）**: hold-out GTは RAGが読むのと同じ抽出パイプラインから機械生成
   （self-scored全問Perfect）。封印案件でも「問題様式・GT生成源」が共にin-distributionのため、
   hold-out 0.98 が実 −0.1333 に転移しなかった。test100の実様式（計算34/比較5/抽出35/参照26）とは
   別分布。
3. **審査ギャップ**: 実gpt-5.2はGemini代理より約0.2辛い（#1で実測）。strict化（SOT-2446）で
   idx17/23/28 の過剰Perfect 3件を検出済み — valid30コミット20問中3問＝15%が審査差だけで反転しうる。
   さらに代理審査自体にノイズ（gate1でpred==GTの idx2 が Missing 判定、idx14 の「わかりません」が
   Incorrect 判定）があり、その振れ幅は実スコアの提出間差と同オーダー。

## Champion喪失の機序（再発防止に直結）

- #3 の commit `0ce7f73` は docs のみ。回答本体（predictions/submission zip）は `.gitignore` の
  `*.zip` / `/artifacts/` / `result/` に該当し保存されず。
- 生成は非決定（LLM）なので同コードの再実行では同一回答セットは再現できない。
- 結果、「実測で最良の挙動」を基準にした差分改善が不可能になり、以降の全ゲートは実測 −0.1333 の
  再構築基盤を守る形になった（ゲートは正しく機能したが、守っている基盤自体が劣位）。

## 推奨アクション（優先度順・人間の判断材料）

1. **検索カバレッジ診断を最優先に（提出不要・ローカルで完結）**: test100の棄権73問について
   「関連文書がtop-kに1件でも入るか」を retrieval-only で全問計測し、取りこぼしの内訳
   （暗号化ファイル / NFDファイル名 / 画像 / 表 / チャンク分割）を特定する。上位勢が1.0である以上、
   答えは全てコーパス内にある — ボトルネックは生成でなく検索・抽出のカバレッジである可能性が最も高い。
2. **回答アーティファクトの永続化**: 以降の全提出について、提出zipと同内容の回答一覧
   （index→回答文字列＋fingerprint）を git管理下に保存する（コーパス原文の再配布にならない形で）。
   champion喪失の再発防止。
3. **提出枠を「設計された実験」にのみ使う**: ほぼ同一挙動の再提出（#6型）を禁止し、1枠ごとに
   仮説を1つ検証する構成（例: champion挙動+新規コミット差分のみ、archetype単位のon/off）で
   実LBからの情報量を最大化する。
4. **ローカルゲートは診断専用に降格**（採用判定に使わない）: 採用＝実LB確認のみ。ρ=−0.09 の証拠が
   ある以上、ローカル改善を昇格根拠にしない（既にSOT-2417系の教訓と同型）。
5. **#3挙動クラス（self-consistency gate + 24コミット水準の保守性）を現行パイプライン上に再構成**し、
   1枠で実測する — 実測済み最良（−0.0333）に最も近い既知の挙動クラスであり、現行 −0.1333 基盤より
   期待値が高い。
